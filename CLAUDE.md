# Hinge — project memory for Claude Code

> Working name: **Hinge**. A personal macOS menu-bar app that reads the MacBook lid-angle sensor and animates the built-in display as the lid closes: the screen leans away, blurs progressively from the far (top) edge, and fades toward black, all driven live by the real hinge angle. It reverses smoothly when the lid opens.
> Owner: Maxwell. Audience: just him. Free, local-only, no distribution.

## Hard facts (do not re-derive; do verify empirically where marked)
- Target hardware: Apple-silicon MacBook Pro, M3/M4/M5 family. Sensor is present on these (verify in Phase 0).
- Sensor: IOKit HID device, VendorID `0x05AC`, ProductID `0x8104`, PrimaryUsagePage `0x20` (Sensor), PrimaryUsage `0x8A` (Orientation). Read **feature report ID 1** (not an input report). Payload is `[reportID, lo, hi]`, 16-bit little-endian.
- **UNVERIFIED:** unit of the 16-bit value. One source says whole degrees, another says 0.01°. Phase 0 must settle it by logging raw values at closed / ~90° / fully open.
- The effect requires ScreenCaptureKit (Screen Recording permission). Phase 1 deliberately avoids it.
- Min deployment target macOS 14. Swift 5.9+/6, AppKit for the menu bar and windows, SwiftUI only for the Preferences window, Metal for rendering.
- **App Sandbox OFF.** HID access to the sensor hub is not reliable inside the sandbox, and this is a personal tool.
- Menu-bar only: `LSUIElement = YES`, no Dock icon, no main window, no notifications.

## Stack and tooling
- Xcode project generated by **XcodeGen** (`project.yml` is the source of truth; do not hand-edit the `.xcodeproj`).
- Sign with the user's free **Apple Development (Personal Team)** certificate. Do NOT use ad-hoc "Sign to Run Locally": the Screen Recording permission is tied to the code signature, so ad-hoc builds re-prompt after every rebuild.
- Project location: `~/code/hinge`. Bundle ID: `com.maxwell.hinge`.
- Tests: XCTest for all pure logic (angle→progress mapping, smoothing, matrices). Rendering is verified by manual QA plus the simulated-angle slider.

## Conventions
- Small files, one responsibility each (see file layout in `ARCHITECTURE.md`).
- All tunable numbers live in one `EffectParameters` struct. No magic numbers in rendering code.
- Everything that consumes an angle takes it through an `AngleSource` protocol so the real sensor and the simulator are interchangeable.
- Never poll or capture when the effect is idle (battery). See the power rules in `ARCHITECTURE.md`.
- Commit at the end of every phase with a message like `phase 1: overlay + blur/dim`.

## Guardrails
- Do not decompile, download, or copy any commercial app or its assets. This is a clean-room build from the public sensor research and the docs here.
- Reading open-source reference projects (`jh3y/lid-plane`, `IuCC123/BendMac`, `samhenrigold/LidAngleSensor`) for approach is fine. Check each license before copying any code, and prefer writing our own.
- Don't add launch-at-login, a global hotkey, auto-update, analytics, or a network layer. They are out of scope.
- Use a name and icon of our own; nothing should say "Macbook Duo" or reuse the original's artwork.
